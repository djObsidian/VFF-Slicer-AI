# VFF Slicer

Препроцессор + постпроцессор для непланарной 3D‑печати на **3‑осевых
FDM‑принтерах**. Берёт STL, строит внутри модели **поле направлений роста**,
деформирует меш так, чтобы его естественные слои стали плоскими, даёт обычному
планарному слайсеру (PrusaSlicer, Cura, …) его нарезать, а затем переводит
планарный g‑code обратно в **криволинейные слои, повторяющие форму детали** —
без лестничного эффекта на кривых верхах и с нависаниями, которые печатаются без
поддержек.

🇬🇧 [English version — README.md](README.md) ·
🛠 [Внутренности и полный справочник — ARCHITECTURE.md](ARCHITECTURE.md)

> **Статус: эксперимент.** Пайплайн деформации провалидирован end‑to‑end на
> реально нарезанном g‑code (inverse кладёт 98.7 % траектории обратно внутрь
> оригинала), реальная печать в процессе. Это не слайсер «в один клик»: тонкие
> фичи и самопересекающиеся меши требуют ручной настройки.
> См. [Ограничения](#ограничения--backlog).

## Установка

Python 3.10+, Windows / Linux / macOS. Зависимости в
[`pyproject.toml`](pyproject.toml):

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate      Linux/macOS:  source .venv/bin/activate

pip install -e .            # ядро: деформация + g-code пайплайн (headless)
pip install -e .[viewer]    # + интерактивный PyVista-вьювер / preview / section
pip install -e .[all]       # + вьювер + FMM-метод глубины (scikit-fmm)
```

Editable‑установка (`-e`) ещё и регистрирует команду `vff`, так что можно
`vff model.stl …` вместо `python -m vff model.stl …`.

**Ядро** (`numpy scipy trimesh rtree embreex`) ставится колёсами даже на свежий
Python (проверено на 3.14). **Вьювер** (`pyvista`+`vtk`) опционален, потому что
колёса vtk отстают от новых релизов Python — headless‑пути (`--export`,
`--gcode-in`, `--deform-mode 3d`) его не импортируют.

## Использование

Основной режим — **полный 3D‑пайплайн** (`--deform-mode 3d`). Три шага:
деформировать → нарезать → развернуть:

```bash
# 1. Экспорт деформированного меша. --subdivide-error подразбивает грубые
#    плоские зоны (например потолок выреза), чтобы они могли выгнуться.
vff part.stl --deform-mode 3d --max-tilt 30 --subdivide-error 0.1 \
    --export deformed.stl --no-viewer

# 2. Нарезать deformed.stl в PrusaSlicer / Cura.
#    ВАЖНО: относительная экструзия (M83), модель в центре стола.

# 3. Развернуть планарный g-code обратно в координаты оригинала.
#    Те же флаги карты, что и на экспорте (см. предупреждение ниже).
vff part.stl --deform-mode 3d --max-tilt 30 \
    --gcode-in deformed.gcode --gcode-out result.gcode \
    --gcode-direction inverse --subdiv-mm 0.5

# Превью результата (родной превью PrusaSlicer не показывает непланарные слои):
vff.preview result.gcode        #  E = экструзии,  T = травелы
```

> ⚠️ **Все флаги, формирующие карту деформации, должны совпадать на экспорте и
> на inverse:** `--max-tilt`, `--pitch`, `--volume`, `--smooth-sigma`,
> `--growth-source`. Иначе обратная карта не совпадёт с нарезанным мешем и слои
> лягут мимо.

### Главные флаги

| Флаг | Что делает |
|---|---|
| `--max-tilt DEG` | **Главная ручка.** Макс. наклон сопла к вертикали, при котором голова печатает — зависит от формы хотэнда/обдува. `20` массивная голова · `30` дефолт · `45` компактное/острое сопло (сильнее непланарность). |
| `--subdivide-error MM` | (только экспорт) Равномерно подразбивает меш, пока худшая ошибка грани не упадёт ниже порога, чтобы плоские зоны из малого числа крупных треугольников могли выгнуться. Попробуй `0.1`. По умолчанию выкл; экспорт подсказывает, когда нужно. |
| `--extrusion-comp-mode` | `vertical` (дефолт, 3‑ось): масштаб E по сжатию слоёв по высоте — верно для вертикального сопла фиксированной ширины. `volume`: масштаб `1/det` (материал‑консервативно, для 4/5 осей как S4). `--no-extrusion-comp` выключает. |
| `--z-slowdown FACTOR` | (gcode) Мягко замедляет F на крутых непланарных ходах: ×1 на плоских → ×FACTOR на склоне 30°+ (например `0.5` режет вдвое самые крутые). Дефолт `1.0` = выкл (планировщик прошивки, напр. Klipper `max_z_velocity`, всё равно жёстко лимитит Z). |
| `--pitch MM` | Размер вокселя (дефолт 1.0). Меньше = тоньше поле, больше RAM. |
| `--smooth-sigma N` | Сглаживание смещений в вокселях (дефолт 2.0). Больше = глаже меш / меньше складок, мягче купола; меньше = резче. |
| `--growth-source` | `bfs` (дефолт) или `geodesic` (сильнее пучит потолки полостей, но глобально портит тонкие фичи — не рекомендуется для деталей с лопастями). |

Интерактивный вьювер (`vff part.stl`, без флагов) показывает воксели / поле
роста / деформированный меш по хоткеям, но пока визуализирует **Z‑only**
(легаси) карту.

## Как работает и зачем

Обычный слайсер режет модель горизонтальными плоскостями. На кривом верхе это
даёт грубую лестницу. Непланарная нарезка вместо этого кладёт **слои,
повторяющие поверхность**. На 5‑осевом сопло наклоняется; на 3‑осевом сопло
вертикально, но Z меняется по ходу движения, и пока угол поверхности под
лимитом (`--max-tilt`), материал ложится нормально.

VFF делает это через **деформ → нарезка → разворот**:

```
 оригинал ──деформ──▶ деформ. меш ──планарная──▶ планарный g-code
   деталь   (слои               нарезка               │
           выпрямлены)        (обычный слайсер)        │ inverse
                                                       ▼
                                    g-code в координатах ОРИГИНАЛА —
                                    плоские слои стали кривыми слоями роста.
```

1. **Поле роста.** Заливаем модель вокселями и «растим» снизу от стола как
   осадок. В каждой точке — локальное *направление печати* (куда тут «вверх»);
   его поверхности уровня — естественные слои.
2. **Деформация (3D‑карта).** Поворачиваем каждый кусочек так, чтобы его
   направление роста смотрело строго вверх, и сшиваем обратно (ARAP / Пуассон).
   Двигаются все три оси, поэтому боковые расстояния сохраняются, а не рвутся.
   Итог: естественные слои становятся плоскими горизонтальными плоскостями.
3. **Нарезка** деформированного меша любым планарным слайсером.
4. **Разворот** g‑code (быстрый векторизованный Ньютон, обратный карте): плоские
   слои слайсера при печати становятся кривыми слоями оригинала.

Три практических детали делают результат печатаемым на 3 осях:

- **Зажим наклона (`--max-tilt`)** держит слои в пределах угла, который
  вертикальное сопло реально печатает.
- **Bed‑blend** держит первые пару миллиметров как тождество, чтобы первые слои
  ложились плоско на стол (сопло не врезается).
- **Компенсация экструзии** масштабирует E под изменение высоты слоя — у
  вертикального сопла ширина дорожки фиксирована, поэтому важно как
  *расстояние между слоями* сжимается/растягивается, а не объём (дефолтный
  режим `vertical`; `volume` — для 4/5 осей).

На тестовом пропеллере 3D‑карта сохраняет боковые расстояния в ~3 раза лучше
наивного Z‑сдвига (CoV длин рёбер 0.044 vs 0.148), удерживает 96 % объёма и
обратима до ~0.0001 мм на 97 %+ точек.

Глубокая математика (BFS‑рост, интегрирование векторов в потенциал, 3‑коорд.
Пуассон, проходы по g‑code) — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Ограничения & backlog

- **Адаптивный ремешинг.** `--subdivide-error` равномерный → тяжёлый (пропеллер
  35k → 562k граней). Конформный адаптивный ремешинг (Rivara longest‑edge
  bisection) дал бы то же качество при ~15× меньшем числе граней без трещин.
- **Несходимость на кончиках** (~2 %, ловит despike‑проход) — карта складывается
  под крутыми нависаниями; лечится меньшим `--max-tilt`.
- **Точечные купола полостей.** Дефолт уже хорошо пучит потолок выреза;
  `--growth-source geodesic` пучит сильнее, но глобально портит тонкие фичи.
  Геодезика **только вокруг внутренних полостей** (детектор «пустота, обёрнутая
  материалом со всех сторон» vs «открытая наружу») дала бы лучшее от обоих.
- **Самопересекающийся / non‑manifold вход** надо чинить перед вокселизацией.
- **Реальная FDM‑печать** результата валидируется сейчас; считай результаты
  экспериментальными.

Есть ещё легаси **Z‑only** деформация (`--deform-mode z-only`, дефолт) и два
g‑code‑режима (`--conform-to`, `--clip-to`) — см. [ARCHITECTURE.md](ARCHITECTURE.md).
